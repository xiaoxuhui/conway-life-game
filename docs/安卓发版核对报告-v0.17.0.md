# 安卓发版核对报告 — v0.17.0（首个固定 debug 签名版本）

- **日期**：2026-09-28
- **issue**：老用户「有新版本却一直装不上」
- **结论**：**已解决并实证**。v0.17.0 的 APK 签名与仓库内 `android/app/debug.keystore` **字节完全一致**；
  v0.16.0 → v0.17.0 需一次性卸载重装，此后可正常覆盖更新。
- **前置**：本机**无 JDK / 无 Android 工具链**，以下全部为**静态核对**（解包 + 二进制解析），
  真机安装验证见第七章，留给肖工。

## 一、为什么要发这一版

代码侧的修复（提交 `99692b6 fix(android): 固定后续 APK 签名基线`：keystore 入库 + `signingConfigs` 显式引用）
**只对"后续构建"生效**，而线上最后一个包仍是 v0.16.0。

**不出包等于没修** —— 装了 v0.16.0 的用户依然升不上去。本次发版补的就是这一步。

问题机理：AGP 在未配 `signingConfig` 时会**为每台构建机现场生成随机 debug key**。
GitHub Actions 每次都是全新 runner → 每次发布签名都不同 → 系统以
`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 拒绝覆盖安装。**首个包看不出问题，发第二个包才炸。**

## 二、v0.16.0 的签名是随机的 —— 实测证据

从 v0.16.0 Release APK 的 APK Signing Block 提取 v2 签名证书，与仓库 keystore 导出证书对比：

| | v0.16.0 线上 APK | 仓库 `debug.keystore` |
|---|---|---|
| Subject | `CN=Android Debug, O=Android, C=US` | `CN=Conway Life Game Debug, O=xiaoxuhui, C=CN` |
| notBefore | **Sep 11 16:32:39 2026 GMT** | Sep 19 14:30:27 2026 GMT |
| SHA-256 指纹 | `B1:4B:96:04:F5:47:87:12:2B:BA:4D:87:D4:3E:15:B8:7E:09:3F:D1:98:9E:AE:63:67:40:B5:CB:4C:7D:A0:46` | `43:77:23:CE:43:1D:1F:7F:EA:85:4D:73:95:9D:7C:E0:61:3B:E2:42:82:A1:EF:D2:EA:0F:4A:DD:08:03:81:BA` |

两条独立证据指向同一结论：
1. **Subject 不同** —— 线上包是 `Android Debug`（AGP 默认模板），仓库 keystore 是项目专名。
2. **notBefore 与发布时间只差 19 秒** —— 证书是构建那一刻现场生成的，不可能是仓库里的固定文件。

（本项与 `docs/安卓打包实施计划.md` 的「签名迁移记录（2026-09-28）」记录一致，此处补齐原始数据。）

## 六、顺手修掉的一个漂移源

`tests/android-shell.test.js` 原先**硬编码** `versionCode` / `versionName`，
导致每次发版要同时改三处（`package.json`、`build.gradle.kts`、测试文件）—— 同一事实维护多份，必然漂移。

改为：

- `versionName` 必须**等于** `package.json` 的 `version`（真源只有一个，不可能不一致）；
- `versionCode` 只校验「**≥ 2 的整数**」；下限 2 是固定历史事实（v0.16.0 为 1），
  而「只增不减」无法从当前状态推导，仍需发版时人工确认 —— 已在 `android/README.md`
  的一致性表里标明**这是清单中唯一靠人的一项**。

**反向探针**（证明新断言不是摆设，实测非推断）：

```
versionName 改 9.9.9 → 失败：build.gradle.kts 的 versionName（9.9.9）必须与 package.json 的 version（0.17.0）一致
versionCode 改回 1   → 失败：versionCode 必须是 ≥ 2 的整数（当前 1）—— v0.16.0 之后只能递增
```

## 附：核对方法可复现

本机无 JDK，核对全部靠两条脚本（无需 Android 工具链）：

1. **APK Signing Block → v2 证书 DER**：
   定位 `APK Sig Block 42`（块的最后 16 字节），读其前面 8 字节的 `size`，
   则块起始 `= magic 偏移 + 8 − size`（**`size` 含末尾 size 与 magic 共 24 字节，漏算即错位 16 字节**）；
   遍历 id-value 对取 id `0x7109871a`，逐层剥长度前缀取 `signers[0].signed_data.certificates[0]`。
2. **AXML 解析**：`AndroidManifest.xml` 是编译后的二进制 XML，
   解析 chunk 头 → 字符串池 → `START_ELEMENT`(0x0102) 的属性表，
   `versionName` 走字符串池、`versionCode` 取 int 型 `data` 字段。
