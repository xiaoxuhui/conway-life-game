# 技术设计

## 1. 技术目标与约束

- 使用原生 HTML、CSS 和 JavaScript，不依赖后端。
- 核心玩法在断网状态下可用。
- MVP 不引入框架、打包器或运行时依赖。
- 业务逻辑与界面渲染分离，使规则可以独立测试。
- 默认规模下优先保证清晰和稳定，再考虑极限性能。

## 2. 计划中的目录结构

以下是开发阶段的目标结构，当前不会提前创建空代码文件：

```text
conway-life-game/
├─ index.html               # 页面结构和静态内容
├─ styles/
│  └─ main.css              # 布局、主题、响应式与可访问性样式
├─ scripts/
│  ├─ life-engine.js        # 纯规则、棋盘状态与序列化
│  ├─ renderer.js           # Canvas 绘制和坐标转换
│  ├─ presets.js            # 预设图案数据
│  ├─ pattern-library.js    # 自定义图案校验、归一化与本地持久化
│  └─ app.js                # 控件、计时器和用户交互
├─ tests/
│  └─ life-engine.test.js   # 核心规则自动化测试
├─ docs/
├─ README.md
└─ .gitignore
```

## 3. 架构分层

### 规则层 `life-engine.js`

职责：

- 创建、读取和更新棋盘状态。
- 计算单个下一代，不接触 DOM 或计时器。
- 统计活细胞数量。
- 放置预设和校验导入数据。

规则层应尽量由纯函数组成，同一输入始终产生同一输出，方便测试和复现问题。

### 渲染层 `renderer.js`

职责：

- 把稀疏无限世界按当前相机绘制到 Canvas。
- 根据元素尺寸和设备像素比生成清晰画面。
- 负责屏幕坐标与世界坐标互转、平移、缩放和视图适应计算。
- 不自行改变棋盘数据。

选择 Canvas 而不是为每个格子创建 DOM 元素，原因是稀疏世界的可见格数随缩放变化，Canvas 更适合相机变换和多尺度绘制。控制按钮仍使用语义化 HTML。

### 应用层 `app.js`

职责：

- 保存当前棋盘、代数、速度和运行状态。
- 连接按钮、数字输入框、键盘和指针事件。
- 管理唯一的演化计时器。
- 在每次状态变化后统一刷新画面和状态文本。
- 管理临时的图案放置状态；只有指针确认时才把预览提交到规则层。

### 图案库层 `pattern-library.js`（v0.3 已实现）

职责：

- 将无限世界中的全部活细胞按最小行、列归一化为从 `[0, 0]` 开始的有限图案。
- 校验名称、说明、尺寸、活细胞数量、坐标和重复名称。
- 读取和写入浏览器本地存储，并把存储异常转换为可读错误。
- 导出不可变的自定义图案列表，不直接操作 DOM、Canvas 或演化计时器。

内置 `presets.js` 继续保持静态、只读；应用层只在展示时合并内置图案与自定义图案，避免用户数据污染源码预设。

### 逻辑门预设（v0.6）

逻辑门由少量可复用的有限构件组合：周期 30 滑翔机枪、真假输入枪、eater、完整滑翔机探针和隔离静物输出端。`presets.js` 在初始化时把紧凑的十六进制行描述转换成普通 `[row, column]` 坐标，再按门的固定相位布局合并并归一化；运行时规则引擎仍只接收普通细胞坐标，不增加特殊逻辑规则。

逻辑门预设增加只读 `logic` 元数据：门类型、输入数组、期望输出、观察代数、五个滑翔机探针格、四个静物终端格和传播方向。应用只读取真实世界中的五个探针格；五格同时符合指定滑翔机相位才得到 1，避免碰撞碎片或单格闪烁误报。旋转或翻转图案时，探针、传播向量与静物终端使用相同几何变换同步更新。

构造依据为 Jean-Philippe Rennard 的 LogiCell 方法：滑翔机表示信号，周期 30 枪提供同步信号，碰撞完成布尔运算，eater 负责清理或检测输出。项目仅保存独立重建并由本地规则引擎验证后的细胞布局，不引入 Java 程序或运行时依赖。

v0.6.1 将构件间距恢复为相位对称布局：NOT 的反向枪与输入相距 41 格；AND、OR 的第二输入相对第一输入偏移 42 格；OR 的平行枪偏移 88 格。验收不再只抽查一真一假，而是分别生成全部输入排列；当时仍采用单格采样，已在 v0.6.2 被完整滑翔机探针替代。

v0.6.2 删除会被滑翔机碰撞扰乱的旧检测结构。每个门改用与所有已知信号轨迹至少留出两格安全间距的 2×2 方块作为静物终端；终端不参与布尔计算。界面状态 `logicOutputs` 记录放置原点、探针、观察代数和锁存结果：NOT 在第 83 代、AND 在第 163 代、OR 在第 255 代读取一次，之后只显示锁存值。结果来自实际五细胞滑翔机，不使用预设中的 `expected` 代替计算。

v0.6.3 为双输入门增加可审计的 `inputOrigins` 元数据。AND、OR 的第二输入相对第一输入使用 `[row + 1, column - 41]`，即 Y 坐标错开 1 格、X 坐标间隔为奇数；归一化、旋转和翻转时与细胞及探针同步变换。新的碰撞布局由规则引擎枚举并用四种输入组合共同筛选：AND 在第 149 代、OR 在第 243 代读取完整滑翔机相位，NOT 仍在第 83 代读取。静物端点重新放置在所有四种轨迹连续 600 代都保持至少两格安全间距的位置。

v0.6.4 按用户的新决定保留 1 格纵向错位，但将第二输入改为 `[row + 1, column - 42]`，使 X 间隔成为偶数 42。规则引擎重新搜索得到 AND 第 150 代的完整滑翔机探针；OR 仍在第 243 代读取，NOT 保持第 83 代。原 v0.6.3 静物端点在新轨迹下继续通过 600 代隔离稳定性验证。

## 4. 状态模型

v0.2 使用 `Set<string>` 保存无边界整数坐标上的活细胞，键格式为 `"row,column"`。未记录坐标为死亡。

应用状态示意：

```js
{
  world: { cells: Set },
  generation: 0,
  running: false,
  stepsPerSecond: 5,
  camera: { centerRow: 0, centerColumn: 0, cellSize: 16 }
}
```

规则计算生成新的集合，避免同一代内的更新互相污染。详细方案见 [无限世界设计方案](infinite-world-design.md)。

## 5. 演化算法

无限世界采用稀疏邻域累计：

1. 遍历每个活细胞。
2. 给周围 8 个候选坐标累计活邻居数。
3. 根据 B3/S23 写入下一状态集合。
4. 完成后整体替换旧集合，代数加 1。

时间复杂度约为 `O(live cells × 8)`，不依赖理论地图尺寸。分块、HashLife 或 Web Worker 仅在真实测量表明需要时引入。

## 6. 运行调度

- 整个应用只允许存在一个计时器句柄。
- “开始”创建调度，“暂停”清除调度并释放句柄。
- 速度变化时安全地重建调度，不立即额外执行一代。
- v0.7.0 通过独立的纯函数校验和归一化手动输入速度；v0.14.0 将范围扩展到 1–1000。`input` 事件只接受范围内整数，`change/blur` 负责恢复空值或把小数、越界值规整到当前范围。
- v0.8.0 新增纯解析模块 `logic-code.js`，只负责把有限语法转换为 `{ gate, inputs, expected, presetId, expression }`，不接触 DOM 或生命世界。应用层用 `presetId` 获取已经通过真值表验证的内置结构，并进入现有可拖动放置预览；`expected` 只用于说明，实际 `O` 值仍由 `signalCells` 检测。解析失败以受控错误返回，任何世界状态修改都发生在解析、预设查找和用户确认位置之后。
- v0.8.1 使用递归下降解析函数式嵌套，限制最多 8 层和 200 字符；该版的横向分级图案仅是过渡实现。
- v0.8.2 保留 AST，并将现有门拆成“常量输入发生器、无输入门体、输出端口”三类可组合部件。嵌套边不再放置父门自己的输入发生器，而是把子门的输出流旋转/翻转到东南方向，再平移到父门对应的东南输入线路。
- 高斯帕枪以 30 代为周期。布线器为同一父门的嵌套输入选择同一个脉冲序号 `k`，把子门在全局连接代的五细胞输出与父门输入端的同相五细胞滑翔机逐格对齐。必要时增大 `k` 拉长线路，直到门体初始包围盒互不干扰。
- 父门最终读取代数为其基础观察代数加 `30 × k`。早于连接脉冲的启动瞬态不作为结果；最终 `O` 仍只由根门完整五细胞探针锁存。常量叶子继续使用已有真假输入发生器，从而保持旧的单门真值表与图案兼容。
- v0.9.0 在函数表达式与顶层赋值之间按括号深度切分逗号。解析器先建立大小写无关的变量表，再递归解析 AST，并在完成后校验缺失、重复和未使用赋值；变量叶子只向 AST 提供 0/1，物理输出仍完全来自生命演化。
- v0.9.0 支持同一父 AND/OR 的两条嵌套边。第一条子电路保持原朝向；第二条沿主对角线转置以分开两套枪体和辅助流，再把整套细胞预演 2 代，同时把其观察代与内部连接代前移 2 代。转置仍保持输出向东南传播，2 代预演使两路输出重新落在父门可接受的 p30 滑翔机相位。两路最终仍由统一连接代逐格对齐到各自输入端口。
- v0.10.0 新增纯模块 `logic-function-library.js`，管理 `{ format, version, functions }`，每项包含 `{ id, name, code, createdAt, updatedAt }`。模块只负责结构、限制、重名、版本和存储错误；应用层在创建或修改前调用 `LogicCode.parse(code)` 验证语义，避免持久化模块反向依赖编译器。
- 函数库使用独立键 `conway-life-game.logic-functions.v1`，与自定义图案库隔离。读取到损坏或未来版本数据时停止本轮写入，保留原始本地数据；空库则正常显示禁用的载入和管理按钮。
- v0.11.0 的函数项升级为 `{ code, inputs: [{ name, defaultValue }] }`，其中 `code` 只保存表达式主体。`LogicCode.createFunctionDefinition` 复用括号深度切分规则，补齐未赋值变量的临时 0 后执行正式解析，因此输入识别不能绕过语法校验；`instantiateFunction` 校验完整输入集合后再生成可执行代码。
- 函数库 v2 读取 v1 时按顶层逗号提取末尾 `名称=0/1`，迁移为输入默认值；没有赋值的旧常量代码保持零输入函数。迁移只发生在内存中，直到用户下一次写入才覆盖存储。
- v0.12.0 在解析前执行纯文本 AST 级宏展开：按括号深度提取实参，把形参以完整标识符替换为带括号实参，再递归展开主体。调用栈用于检测直接/间接循环，最大展开深度仍为 8；展开结果必须通过现有 `parse`，因此自定义函数不能绕开 B3/S23 逻辑门语法。
- v0.13.0 门体套件公开每座枪的固定 `zoneCells`，编译器同时保留该枪独立运行所需的 `referenceCells`。镜像、转置、相位预演和平移必须同步变换安全元数据。验证器预计算各枪 30 个参考相位，并逐代比较完整世界在固定占用区内的状态。
- 安全验证时域为 `4 × max(width, height) + 120` 代：滑翔机每 4 代沿对角线移动一格，前项覆盖候选包围盒，后项覆盖四个 p30 周期。组合器按 240、360、480、720 代基础线路余量搜索；首个通过候选才进入预览。
- v0.13.1 把解析入口拆为 `parse` 与 `parseExpanded`：前者继续校验用户输入的 200 字符上限，后者只供应用层解析已完成循环、参数量和八层深度检查的宏展开结果，并设置 5000 字符硬上限。函数定义保存时同样在展开后执行该上限检查。这样调用名 `GF_2` 不需要特殊分支，短调用不会因内部替换后的长度被误判为用户输入过长。
- v0.13.2 将嵌套解析器改为按 `OR → AND → NOT → primary` 分层的递归下降语法。`primary` 统一处理常量、变量、括号分组和 `AND/OR/NOT(...)` 函数调用，因此同一表达式可混用中缀与函数写法；AST 创建时计算真实门深度并继续限制为 8。宏展开后残留的非内置函数调用在解析入口报告具体名称。
- v0.13.3 保留同步 `composePattern` 供纯测试与兼容调用，同时新增 `composePatternAsync` / `validateGunSafetyAsync`。异步验证执行完全相同的逐代世界与枪体参考演化，但按约 12ms 时间预算调用可注入的 `yieldControl`，默认用零延时计时器把控制权交还浏览器；进度回调只在让出执行权时触发。应用层用 `AbortController` 管理单个生成任务，第二次提交中止任务，并以 `aria-busy`、按钮文字和状态区表达运行状态。选择协作式时间片而非独立 Worker，是为了保持 `file://` 双击运行兼容。
- v0.13.4 将异步枪体验证的默认时间预算从 12ms 提高到 40ms。算法、候选和时域不变，只减少 `setTimeout(0)` 切换与 DOM 进度更新频率；40ms 仍低于约 50ms 的长任务边界，并在每次让出后检查取消信号。验证器同时预计算每组枪体占用区的 30 个参考相位，确认第 30 代占用与第 0 代相同后按 `generation % 30` 复用；不满足周期的普通候选自动退回逐代参考演化。时间预算定义为公开常量并由回归测试锁定。
- v0.13.5 为所有安全区预计算“坐标 → 所属枪组”的反向索引。逐代验证先确认每组参考相位中的区内活细胞都存在，再扫描当前世界的活细胞，凡落入一个或多个安全区者都必须在对应枪组的参考相位中存在。该双向包含关系与原来的矩形逐格相等判断等价，同时跳过双方都为空的大量坐标；重叠安全区按所属组逐一核对。同步和异步验证共用同一比较函数，时间片和安全时域不变。
- v0.8.4 在 OR 输出接入 NOT 时增加一个固定于根 NOT 局部坐标的 Eater 1。它位于 OR 辅助东南滑翔机流与根枪体之间，只吸收辅助流；主输出仍在独立输入线上进入 NOT。测试在每个 30 代周期检查根枪体全部细胞，而不是只检查最终探针。
- v0.8.5 将 OR 门内部 Eater 1 的原始列坐标从 21 调整为 20（归一化后整体左移一格）。门体套件公开 `eaterCells` 供长期结构测试使用；测试覆盖四种输入的 900 代 p30 恢复、最终探针和静物终端。
- 标签页进入隐藏状态时自动暂停。
- 视觉帧率与演化速度相互独立；高速模式必须允许一帧推进多代且只渲染最终状态。
- v0.14.0 已将主循环改为 `requestAnimationFrame` 累积时间方案。`speed-control.js` 根据帧间隔累积小数代数，限制单次帧间隔为 250ms、总积压为目标速度的 0.25 秒且至少 1 代。应用层在约 10ms 计算预算内逐代调用规则引擎和逻辑探针，只在循环结束后绘制一次；每约 500ms 用已完成代数计算实际速度。暂停、隐藏页面和运行中改速都会清空积压与测量窗口。
- v0.14.1 为超过 5 门的 AST 增加四种布局策略：固定转置第二子树、固定转置第一子树，以及按节点深度奇偶交替选择转置分支。转置继续配套预演 2 代恢复滑翔机相位；每个布局与间距组合都经过同一 `normalizeCircuit` 和完整安全验证。大型树优先搜索按层交替策略，避免用户报告的 15 门结构先耗时淘汰 21 个已知不安全候选；小型树只使用原策略，保持既有结构不变。
- v0.14.2 将原固定 `nested.length × 20` p30 脉冲偏移提升为候选参数 `branchPulseSpacing`。大型结构按 20、40、80 搜索；偏移参与每个父节点的子门源代数、对齐代数和整体平移，因此会移动完整递归子电路而非单个信号。候选键由布局、通道间隔、线路余量组成；异步进度和最终图案的只读 `routing` 元数据公开三项取值。大型结构和显式宽通道在归一化前调用整体方向校正，镜像会同步转换所有线路与枪体安全数据；20×p30 的既有小型结构保留原坐标，以兼容已验证的 OR→NOT 保护器几何。
- v0.15.0 将字符串键集合的一步 B3/S23 演化统一为 `LifeEngine.nextCellSet`；逻辑系统拆为 `logic-parse`、`logic-expand`、`logic-compile`、`logic-safety` 四个 UMD 子模块，`logic-code` 仅保留组合搜索和兼容门面。相位预演现在同步推进实际细胞、输出探针、终端、枪体参考和连接探针，并让观察代数保持在统一的相对时间轴上。

## 7. 绘制输入

统一使用 Pointer Events 支持鼠标、触控笔和触摸：

- `pointerdown` 时读取起点状态，确定本次手势是绘制还是擦除。
- `pointermove` 时只把经过格子设置为目标状态，不执行 toggle。
- 中键、右键或空格加左键进入平移；滚轮以光标为中心缩放。
- 两个触摸指针进入平移缩放手势，并取消单指绘制。
- 使用指针捕获处理移出 Canvas 后的结束事件。
- 运行中忽略棋盘编辑输入。

### 图案放置状态机（v0.5）

放置状态保存 `{ pattern, row, column, pointerId }`。`pattern` 是不可变的有限坐标集合，`row/column` 是其左上角世界坐标，`pointerId` 只在拖动期间存在。渲染层把它画成半透明叠层，但不写入世界。

- 进入：暂停演化，把预览初始化到相机中心。
- 移动：将指针所在格与图案中心对齐；拖动和悬停使用同一坐标计算。
- 提交：调用 `placePattern(..., replace=false)` 合并细胞，代数归零，继续留在放置状态。
- 变换：`presets.js` 返回旋转或翻转后的新不可变图案，原内置/自定义记录保持不变。
- 退出：清除临时状态；`Esc`、右键、完成按钮以及会替换世界的操作都触发退出。

渲染层在活细胞之上绘制预览；普通预览使用半透明强调色，与已有活细胞重叠的位置使用暖色提示。窗口尺寸改变时保留并重绘最近一次预览。

## 8. 导入/导出格式

v2 自有 JSON 格式：

```json
{
  "format": "conway-life-game",
  "version": 2,
  "generation": 0,
  "alive": [[-1, 0], [0, 1], [1, -1]],
  "view": { "centerRow": 0, "centerColumn": 0, "cellSize": 16 }
}
```

导入时依次校验：文件大小上限、JSON 语法、格式名、版本、代数、有符号安全整数坐标和可选视图。只有全部通过后才替换当前状态。继续接受 v1 固定棋盘文件，坐标原样迁移并以旧棋盘中心初始化视图。

## 9. 测试策略

### 规则单元测试

- 空棋盘保持为空。
- 单个细胞下一代死亡。
- 2 × 2 方块保持不变。
- 闪烁器周期为 2。
- 滑翔机经过 4 代后平移一个对角格。
- 负坐标、跨旧边界和远离原点的图案按相同规则演化。
- 输入状态不会被 `nextGeneration` 原地修改。

### 交互测试

- 开始/暂停不会产生重复计时器。
- 单步只增加一代。
- 拖动始终是连续绘制或连续擦除。
- 清空、随机、预设能正确暂停并重置代数。
- 速度标签与实际周期一致。

### 人工验收

- Chrome、Edge、Firefox 各完成一次核心流程。
- 桌面宽度、窄窗口和手机宽度进行视觉检查。
- 仅键盘完成开始、暂停、单步和清空。
- 断网后重新打开仍可使用。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本地 `file://` 对模块或文件操作有限制 | 双击运行失败 | MVP 使用普通脚本；导入用文件选择器；开发后在全新环境实测 |
| Canvas 在高分屏模糊 | 可读性下降 | 按设备像素比设置内部分辨率 |
| 手机格子过小 | 难以绘制 | 限定棋盘规模，提供预设，评审缩放/滚动方案 |
| 计时器重复启动 | 跳代、性能问题 | 单一句柄与状态守卫，并编写交互测试 |
| 导入恶意或巨大文件 | 卡顿或状态损坏 | 大小、结构和坐标范围校验；验证通过后再提交状态 |

## 11. 技术验证结论

- Canvas 会根据实际显示尺寸和设备像素比重建内部像素尺寸；桌面与手机宽度下均保持 3:2 比例、完整显示且非空白。
- Pointer Events 的鼠标点击和拖动已在真实浏览器通过；真实触摸设备手势仍需后续人工补测。
- JSON 导入、非法文件保护和导出反馈已在本地静态服务器环境通过。
- 页面仅使用传统本地脚本和相对资源，不使用 ES Module、网络请求或远程资源。自动化浏览器安全策略禁止 `file://` 导航，因此双击运行保留为人工验收项。

## 12. 自定义图案存储设计（v0.3 已实现）

本地存储键：`conway-life-game.custom-patterns.v1`。

```json
{
  "format": "conway-life-pattern-library",
  "version": 1,
  "patterns": [
    {
      "id": "custom-稳定且不可猜测的本地标识",
      "name": "我的滑翔机组合",
      "description": "两个相向移动的滑翔机",
      "width": 12,
      "height": 8,
      "cells": [[0, 1], [1, 2]],
      "createdAt": "2026-08-19T12:00:00.000Z",
      "updatedAt": "2026-08-19T12:00:00.000Z"
    }
  ]
}
```

约束：

- 名称去除首尾空格后长度为 1–30 个字符；说明最多 120 个字符。
- 单个图案最多 50,000 个活细胞，宽高均不得超过安全整数范围。
- 首版最多保存 200 个自定义图案，并在写入前检查序列化后的总大小不超过 4 MB。
- 坐标必须是非负安全整数且位于声明宽高内；重复坐标去重。
- 写入采用“先完整序列化并校验，再一次性替换存储值”，禁止部分更新。
- `localStorage` 不可用、空间不足或数据损坏时返回错误；损坏数据不自动覆盖，保留原字符串供用户导出或恢复。
- 当前世界存档 v2 与图案库格式彼此独立，避免导入一个局面时意外替换用户的全部图案。

归一化规则：取当前世界的 `minRow` 和 `minColumn`，每个活细胞转换为 `[row - minRow, column - minColumn]`；宽高由最大归一化坐标加一得到。该过程保留所有相对位置，同时去除无限世界中的绝对位置。

测试需覆盖：空世界、负坐标、大间距、重复坐标、名称规范化、重名、数量/大小上限、存储异常、损坏数据、增删改后刷新恢复，以及内置图案不可变。
