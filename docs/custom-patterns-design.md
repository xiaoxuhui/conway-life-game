# 自定义图案库设计方案

## 1. 目标

让用户把自己绘制或演化得到的当前形状保存为可重复使用的图案，并在以后重新打开页面时继续使用。整个能力保持零后端、离线和本地优先，不改变内置经典图案。

本方案最初只完成产品与技术设计；v0.3 已按本方案实现并完成验收。

## 2. 首版范围

首版包含：

- 保存当前世界的全部活细胞为自定义图案。
- 名称、说明、尺寸和活细胞数预览。
- 本地持久化，刷新或重新打开页面后仍存在。
- 自定义图案的放置、重命名、更新和删除。
- 内置图案与“我的图案”分组展示。
- 明确处理空世界、重名、数据损坏和存储空间不足。

首版不包含：

- Canvas 矩形框选或套索选择。
- 云同步、多设备同步和账号。
- 在线图案市场、分享链接或社区发布。
- RLE 图案库导入导出；单独的自定义图案库 JSON 文件列为后续增强。
- 为图案自动识别“静物、振荡器、飞船”等类别。

## 3. 核心产品决策

### 3.1 保存什么

保存按钮捕获“当前这一刻世界中的全部活细胞”。绝对世界坐标被移除，所有细胞按最小包围盒左上角归一化。因此：

- 图案在负坐标或百万格外都能正确保存。
- 多个分离结构会作为一个组合图案保存，相对间距保持不变。
- 保存不会暂停后再演化一代，也不会改变当前世界、代数或相机。
- 运行中触发保存时先暂停，再对暂停后的确定状态拍快照。

首版不做框选，因为框选会与左键绘制、空格平移和触控手势竞争。若用户只想保存世界的一部分，应先导出当前世界作为备份，再清空不需要的结构后保存图案。

### 3.2 保存在哪里

自定义图案存入浏览器当前来源的 `localStorage`：

- 双击 `index.html` 使用 `file://` 来源的本地存储。
- 通过本地静态服务器打开时，存储属于对应的 `http://127.0.0.1:端口` 来源。
- 两种打开方式的浏览器存储通常互不共享，这是浏览器安全模型的结果，界面和 README 必须说明。

因此后续建议增加“导出我的图案库”，用于备份和在不同打开方式间迁移，但它不是首个实现切片的阻塞项。

### 3.3 如何处理内置图案

- 内置图案继续来自源码，只读且永远不会被用户操作覆盖。
- 用户可以放置内置图案、修改它，再通过“保存为图案”创建独立副本。
- 自定义图案使用独立 ID；显示名称可修改，但 ID 不随重命名改变。

### 3.4 如何处理重名

名称比较前去除首尾空格，并使用中文用户可预期的不区分英文大小写比较。

- 新建时发现重名：保持对话框内容，不保存，提供“改名”和“更新现有图案”两条明确路径。
- “更新现有图案”会替换其细胞、尺寸、说明和更新时间，但保留 ID 与创建时间，并要求确认。
- 不允许自定义图案使用与另一自定义图案相同的规范化名称；可以与内置图案同名，因为界面有分组和“内置/我的”标识。

## 4. 用户流程

### 4.1 新建图案

1. 用户绘制、导入或演化出目标形状。
2. 点击“保存为图案”。若正在运行，应用先暂停。
3. 对话框展示缩略图、`宽 × 高`、活细胞数，并提供名称和说明输入。
4. 用户保存；成功后出现“已保存到我的图案”，选择框自动定位到新图案。
5. 当前世界完全不变，避免“保存”被误解为“重新放置”。

### 4.2 使用图案

1. 在选择框的“我的图案”分组选择图案。
2. 页面显示说明、尺寸和活细胞数。
3. 点击“放置”，按现有规则替换世界、代数归零并自动适应视图。

### 4.3 管理图案

1. 点击“管理”，打开对话框并列出全部自定义图案。
2. 选择一个图案后可重命名、修改说明或删除。
3. 删除要求确认并说明不可撤销；确认后才写入存储。
4. 若被删除图案正处于选择状态，选择框回到第一个内置图案；当前世界不变。

## 5. 界面草图

```text
经典图案
┌──────────────────────────┐
│ 内置图案                 │
│   滑翔机                 │
│   闪烁器                 │
│ 我的图案                 │
│   双滑翔机               │
└──────────────────────────┘
[放置] [保存为图案] [管理]

┌ 保存为图案 ─────────────────────┐
│  [缩略图]   12 × 8 · 18 个活细胞 │
│  名称 *  [双滑翔机____________] │
│  说明    [相向移动____________] │
│                       [取消][保存]│
└─────────────────────────────────┘
```

手机端对话框占据接近全宽，操作按钮保持至少约 44 像素高；列表和表单可纵向滚动，但背景页面固定。对话框打开时焦点进入标题或第一个输入框，`Esc` 关闭，关闭后焦点回到触发按钮。

## 6. 数据与模块设计

新增 `scripts/pattern-library.js`，只负责纯图案逻辑和存储适配，不操作 Canvas：

- `normalizeWorld(world)`：返回归一化图案或空世界错误。
- `validatePattern(pattern)`：验证名称、说明、尺寸、坐标和数量上限。
- `createPattern(input, clock, idSource)`：创建稳定 ID 和时间戳。
- `updatePattern(library, id, changes)`：不可变更新。
- `deletePattern(library, id)`：删除指定自定义图案。
- `loadLibrary(storage)` / `saveLibrary(storage, library)`：版本化读取和原子写入。

`presets.js` 不改为可变数组。`app.js` 获取两类列表后创建带 `<optgroup>` 的选择框，并根据 `builtin:` 或 `custom:` 前缀解析选择来源。

详细 JSON 格式和限制见 [技术设计](technical-design.md#12-自定义图案存储设计v03-计划)。

## 7. 错误与边界处理

| 情况 | 处理 |
| --- | --- |
| 当前世界为空 | 禁用保存按钮，并提示“先绘制一些细胞” |
| 名称为空或过长 | 表单内联提示，保持输入内容 |
| 自定义名称重复 | 不覆盖；要求改名或明确更新 |
| 图案超过 50,000 个细胞 | 拒绝保存，当前世界不变 |
| 图案跨度极大 | 允许到安全整数范围，但在预览中使用适应视图；同时受 4 MB 总大小限制 |
| 达到 200 个图案或 4 MB 预算 | 拒绝新增，提示删除或未来导出备份 |
| `localStorage` 不可用/已满 | 保持表单和世界，展示可复制的 JSON 兜底 |
| 存储内容损坏 | 不自动清空或覆盖；隔离损坏内容并提示恢复/导出 |
| 删除当前所选图案 | 选择回到内置首项，世界不变 |

## 8. 验收条件

- [ ] 负坐标世界保存后，图案坐标从 `[0, 0]` 附近开始且形状、间距完全一致。
- [ ] 保存不会改变当前世界、代数、相机或运行规则。
- [ ] 刷新页面后自定义图案仍在“我的图案”分组，并能正确放置。
- [ ] 内置图案不能重命名、删除或被同名自定义图案覆盖。
- [ ] 空名称、重复名称、超限图案和存储异常均不会破坏已有图案库。
- [ ] 更新保留图案 ID 与创建时间，修改更新时间；删除只影响目标图案。
- [ ] 选择框、保存对话框和管理对话框可用鼠标与键盘完成完整流程。
- [ ] 桌面与手机宽度下没有按钮遮挡、文字溢出或页面级横向滚动。
- [ ] 现有世界 JSON v1/v2 导入导出行为不受影响。

## 9. 测试策略

### 自动化测试

- 归一化：正坐标、负坐标、百万格外坐标、多分离结构和空世界。
- 校验：名称边界、说明边界、重复名称、非法坐标、重复坐标、细胞数和总大小限制。
- 持久化：首次空库、保存后重载、增删改、版本不支持、JSON 损坏、配额异常。
- 兼容：静态内置图案不可变，现有世界存档格式不变。

### 浏览器验收

- 绘制 → 保存 → 刷新 → 选择 → 放置的完整闭环。
- 内置图案修改后另存为、自定义重名更新和删除确认。
- 存储失败、长名称、200 项列表和空库状态。
- 桌面键盘焦点、`Esc` 关闭、手机纵向布局。

## 10. 设计自评审

| 评审项 | 结论 |
| --- | --- |
| 是否满足“自定义并保存” | 通过；覆盖创建、持久化、再次放置和管理 |
| 是否保持零后端和离线 | 通过；只使用本地存储 |
| 是否破坏无限世界坐标 | 不破坏；保存时只做相对坐标归一化 |
| 是否破坏内置预设 | 不破坏；静态内置库与用户库严格分离 |
| 是否破坏现有世界存档 | 不破坏；图案库使用独立格式和存储键 |
| 是否存在静默数据丢失 | 已规避；重名、删除、更新和损坏数据均不静默覆盖 |
| 是否过度扩大首版范围 | 可控；明确暂缓框选、云同步、RLE 和在线分享 |
| 是否可测试 | 通过；领域逻辑独立模块，时钟与 ID 来源可注入 |
| 是否兼顾电脑使用 | 通过；主流程以鼠标和键盘为基准，触屏仅做响应式兼容 |

自评审结论：方案通过。“首版保存整个当前世界、不做框选”已由用户确认，并已在 v0.3 实现。
